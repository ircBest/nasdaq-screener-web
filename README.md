# NASDAQ IT 스크리너

정량 조건으로 NASDAQ IT 종목을 매일 스캔하고, **발생한 신호를 이후 시장에서 정직하게 추적·검증하는** 자동화 리서치 시스템

> **현재 이 전략은 시장(QQQ)에 지고 있습니다.**
> 이 저장소는 그 결과를 숨기지 않고 그대로 공개합니다.
> 그것이 이 프로젝트가 하려는 일의 전부입니다.

---

## 1. 이 프로젝트가 하려는 것

시중에는 종목을 골라주는 도구가 많습니다. 대부분은 **자기가 고른 종목이 이후에 어떻게 됐는지 기록하지 않습니다.** 기록하더라도 좋았던 것만 남기거나, 나중에 조건을 바꿔서 과거를 다시 계산합니다.

이 프로젝트는 반대 방향을 목표로 합니다.

```
오늘 조건을 만족한 종목이 무엇인가       ← 흔한 것
그 종목이 이후 실제로 어떻게 됐는가       ← 이 프로젝트가 하는 것
같은 기간 시장보다 나았는가              ← 판단이 가능해지는 지점
```

세 번째 질문에 답할 수 없으면 앞의 두 개는 의미가 없습니다. "5일 수익률 -1.5%"는 같은 기간 시장이 -4%였는지 +2%였는지 모르면 좋은지 나쁜지 판단할 수 없기 때문입니다.

## 2. 현재 성과

**2026-09-02 기준**

| 지표 | 값 |
|---|---|
| 누적 신호 | 589 |
| 성과 확정 | 216 |
| 추적 중 | 373 |
| **5일 평균 수익률** | **-1.47%** |
| **같은 기간 시장 (QQQ)** | **+0.31%** |
| **초과수익 (알파)** | **-1.78%p** |
| 시장을 이긴 신호 비율 | 33.3% |
| 5일 승률 | 37.96% |
| 평균 승리 / 평균 손실 | +3.58% / -4.56% |

### 이 숫자를 어떻게 읽어야 하는가

**시장은 올랐는데 신호는 잃었습니다.** 덜 잃은 것이 아니라 못 번 것입니다. 이 기간만 놓고 보면 아무것도 하지 않고 QQQ를 보유하는 편이 나았습니다.

동시에, 성과가 확정된 진입 세션은 **4일뿐**입니다. 전략을 폐기할 근거로도, 유지할 근거로도 부족합니다.

## 3. 측정을 신뢰할 수 있게 만드는 것들

이 프로젝트에서 실제로 공들인 부분은 신호를 만드는 조건이 아니라 **결과를 정직하게 재는 장치**입니다.

### Point-in-Time 아카이브

조건을 통과한 종목만이 아니라 **매일 검사 대상 전체(약 318종목)를 그대로 보존**합니다. RSI 62짜리 종목까지 남깁니다.

덕분에 나중에 "기준이 달랐다면?"을 **다시 스캔하지 않고 과거에 대해 계산**할 수 있고, 미래 정보가 새어 들어가지 않습니다. 시중 백테스트가 가장 흔하게 오염되는 지점입니다.

### 중복 세션 제거

워크플로는 한국시간 아침에 도는데, 그 시각에는 미국 시장이 아직 열린 적이 없어 **직전 세션의 종가**를 봅니다. 주말과 휴장일에는 새 세션이 없어 같은 가격이 며칠씩 반복됩니다.

```
KST 08-22(토) → 08-21(금) 종가
KST 08-23(일) → 08-21(금) 종가   중복
KST 08-24(월) → 08-21(금) 종가   중복
```

이것을 세면 같은 포지션 하나가 독립 신호 3개로 계산됩니다. 실측에서 **연속 관측일 쌍의 56.7%가 진입가까지 동일**했습니다.

종목별로 실제 가격 바 날짜를 기록해 중복을 걸러냅니다. 일부 종목만 데이터가 갱신된 날도 종목 단위로 정확히 처리됩니다.

### 벤치마크 대비 초과수익

모든 성과를 **같은 구간의 QQQ와 나란히** 기록합니다.

```
초과수익 = 신호 수익률 − 같은 기간 시장 수익률
```

진입 시점은 신호와 정확히 맞춥니다. 관측일이 주말이면 직전 거래일 종가를 쓰므로, 신호의 진입가와 같은 순간이 잡힙니다.

### 다중검정 보정

수백 개의 조건 조합을 훑고 나서 "가장 좋은 것"을 고르면, 순전히 우연으로도 훌륭해 보이는 조합이 반드시 나옵니다. 전체 승률 대비 단측 이항검정으로 p-value를 구하고 **Benjamini-Hochberg FDR**로 보정합니다.

표본이 서로 독립이 아니라는 한계(같은 종목이 연속일에 등장, 같은 날 신호는 시장 움직임을 공유)를 결과 파일에 명시합니다. p-value는 낙관적인 하한으로 봐야 합니다.

### 시계열 홀드아웃

관측 날짜를 시간순으로 나눠 앞쪽으로만 전략을 고르고 **뒤쪽(보지 않은 기간)에서 평가**합니다. 두 승률이 크게 벌어지면 과최적화입니다.

### 전략 다중 추적

가장 중요한 장치입니다.

데이터를 보고 기준을 고치면 그 기준이 그 데이터에서 좋아 보이는 것은 당연합니다. 시험 문제를 보고 답을 고른 것과 같습니다.

그래서 **여러 기준을 동시에, 앞으로** 굴립니다.

| 전략 | 조건 |
|---|---|
| 기준선 | 현재 운영 조건 |
| 대안 A | 과매도 기준을 좁힘 |
| 대안 B | 전통적 과매도 기준 |
| 대안 C | 과매도 + 재무 조건 |

같은 Observation에 나란히 적용되므로 서로 간섭하지 않고, 아직 아무도 보지 않은 구간에서 순위가 나옵니다.

## 4. 알려진 한계

숨기면 나머지 숫자도 믿을 수 없게 되므로 그대로 적습니다.

**표본이 적습니다.** 성과가 확정된 진입 세션 4일. 어떤 결론도 내리기에 이릅니다.

**신호가 서로 독립이 아닙니다.** 최근 스캔에서 신호의 약 52%가 반도체 계열입니다. 하루 69개 신호는 69개의 독립 베팅이 아니라 소수의 섹터 베팅에 가깝습니다. 통계적 유효 표본은 기록된 건수보다 적습니다.

**벤치마크가 종목 구성과 완전히 맞지 않습니다.** 신호는 시총 중앙값 약 2.8B의 중소형주 중심인데 QQQ는 메가캡 중심입니다. 현재의 초과수익에는 종목 선정 능력 외에 섹터·사이즈 기울기가 섞여 있습니다.

**거래비용이 반영돼 있지 않습니다.** 종가 진입 가정이고 슬리피지·스프레드가 0입니다. 중소형주에서는 실재하는 비용입니다.

**위험관리가 5일 기준으로는 거의 작동하지 않습니다.** 목표가·손절가를 계산해 표시하지만 216건 중 17건(8%)만 도달합니다. 기록되는 수익률은 5일 단순 보유 기준이며, 계획대로 청산했을 때와의 차이는 현재 데이터에서 약 0.07%p입니다.

**MAX 지표는 성과가 아닙니다.** "발생 이후 최고점"의 평균이라 구조적으로 거의 항상 양수입니다(신호의 76.9%가 양수, 실제 수익은 38.0%). 사후에 최적 시점에 팔았다는 가정이므로 실현 불가능한 숫자입니다.

## 5. 시스템 구조

```
GitHub Actions (매일 자동)
        │
        ▼
   NASDAQ 종목 수집 ──── SEC 상장 목록 (주기적 갱신)
        │
        ▼
   섹터 / 시총 / 데이터 필터        약 318종목
        │
        ▼
   기술적 지표 + 재무 데이터
        │
        ▼
   Observation 전량 보존 ─────────► Point-in-Time 아카이브
        │
        ├──────────────┬──────────────┬──────────────┐
        ▼              ▼              ▼              ▼
     전략 A         전략 B         전략 C         전략 D
        │              │              │              │
        └──────────────┴───────┬──────┴──────────────┘
                               ▼
                    시세 추적 + 벤치마크(QQQ)
                               │
                               ▼
              성과 / 통계 / BSI / 전략 비교
                               │
                               ▼
                    공개 웹 저장소 동기화
                               │
                               ▼
                         웹 대시보드
```

### 저장소 구성

| 저장소 | 공개 | 내용 |
|---|---|---|
| `nasdaq-screener` | 비공개 | 수집 / 스크리닝 / 추적 / 통계 (Python) |
| `nasdaq-screener-web` | 공개 | 대시보드 + 결과 데이터 (이 저장소) |

### 웹 프론트엔드

```
index.html
├── css/style.css
└── js/
    ├── utils.js    포맷 / 이스케이프 / 공통 유틸
    ├── data.js     JSON 로딩 / 스키마 정규화
    ├── ui.js       BSI / 통계 / 카드 / 전략 비교 렌더링
    └── main.js     진입점 / 필터 / 로딩 오케스트레이션
```

빌드 도구와 의존성 없이 순수 HTML/CSS/JS로 동작합니다. 데이터 계층과 표시 계층이 분리돼 있어 데이터 갱신만으로 화면이 반영됩니다.

**전송량**: 첫 방문 약 353KB, 재방문은 ETag 조건부 요청으로 본문 전송 없음. 개별 신호의 기간별 성과(약 230KB)는 해당 섹션을 펼칠 때만 받습니다.

### 공개 데이터

| 파일 | 내용 |
|---|---|
| `data.json` | 스캔 요약 |
| `latest_signals.json` | 최신 신호 목록 |
| `signals.json` | 누적 신호 |
| `performance.json` | 신호별 기간 성과 / 초과수익 / MFE / MAE |
| `statistics.json` | 집계 통계 |
| `bsi.json` | 기간별 지수 + 경과일 곡선 |
| `strategies/` | 전략 비교 |

## 6. 무엇이 공개되고 무엇이 아닌가

**공개** — 시스템 구조, 데이터 흐름, 추적 방법론, 검증 장치, 신호의 모든 값(가격·RSI·목표가·손절가·이후 성과), 웹 구현 전체.

**비공개** — 수집·스크리닝·추적 파이프라인의 Python 구현.

한 가지는 분명히 해둡니다. **조건 자체는 비밀이 아닙니다.** 공개된 신호 데이터를 보면 RSI 임계값과 ATR 배수는 그대로 드러납니다. 애초에 RSI 과매도는 교과서에 있는 지표입니다.

이 프로젝트가 가치를 두는 곳은 조건이 아니라 **그 조건을 정직하게 검증하는 장치**입니다. 조건은 언제든 바뀔 수 있고, 실제로 지금 네 가지를 동시에 시험하고 있습니다.

## 7. 앞으로

**단기** — 데이터 축적. 전략 다중 추적의 out-of-sample 결과 확인. 이 구간에서는 실제 매매를 하지 않습니다.

**중기** — 벤치마크 다층화(섹터·사이즈 기울기 분리), 상위 N개 포트폴리오 구성 규칙, 거래비용 반영, 계획 실행 기준 성과 병기.

**장기** — 사용자가 자기 조건을 정의하면 시스템이 앞으로 추적해 정직한 성과를 돌려주는 검증 도구.

## 면책

본 프로젝트는 **투자자문 서비스가 아닙니다.** 여기의 어떤 내용도 특정 종목의 매수·매도 권유가 아닙니다.

- 게시되는 신호는 정량 조건의 사후 검증 기록이며 투자 판단의 근거로 제공되지 않습니다
- 과거 성과는 미래 수익을 보장하지 않습니다
- 표본이 부족하고 위에 명시한 한계가 존재합니다
- 데이터는 자동 수집되며 원천 데이터의 오류·지연·누락이 있을 수 있습니다
- 투자 판단과 그 결과에 대한 책임은 전적으로 이용자 본인에게 있습니다
